# F2 · API Connections & Architectural Technology Choices

This document provides a comprehensive technical overview of the external API clients integrated into AUDY, explains the capabilities and constraints of each provider, details the purpose of **Spotify** alongside **Deezer**, and formalizes the technical justification for the architectural evolution in **technical English**.

---

## 1. Technical Justification & Engineering Trade-Offs

### Context & Problem Statement
During Sprints 1 and 2, the AUDY system was initially conceived to leverage the **Spotify Web API** for song searching and collaborative filtering recommendations (`/v1/recommendations`), with **MusicBrainz** serving as an open fallback for tag enrichment (RNF-05).

However, in late 2024 and throughout current developer environment revisions, Spotify introduced severe restrictions to its **Standard Developer Mode**:
1. **Endpoint Access Revocation**: The endpoints `/v1/recommendations` and `/v1/artists/{id}/related-artists` were deprecated or blocked for standard developer accounts, requiring an extended quota review that is incompatible with academic coursework and independent testing.
2. **Missing Popularity Metadata**: Spotify's search endpoint in standard mode ceased returning track popularity values (or populated them with `null`/`0`), forcing recommendation systems to assign flat fallback popularity scores (e.g., 50).
3. **Strict Query Limits (HTTP 400)**: Any search query containing `limit > 10` automatically threw an `HTTP 400 (Invalid limit)` exception on modern accounts, requiring strict chunked pagination.
4. **Mandatory OAuth Credentials**: Requiring a registered `Client ID` and `Client Secret` with whitelisted redirect URIs imposed friction for course graders, peer evaluations, and automated continuous testing.

### Technological Resolution: The Deezer Web API Integration
To resolve these obstacles while upholding the course's academic integrity and requirement for **zero hardcoded knowledge**, the team engineered a dedicated client for the **Deezer Web API** (`DeezerAPIClient.java`):

- **Zero-Friction Authentication**: Deezer's public endpoints require no API keys, client secrets, or OAuth handshakes, guaranteeing that the application executes out-of-the-box on any Java 11+ machine.
- **Dynamic Collaborative Recommendation Graph**: Deezer exposes `GET /artist/{id}/related`, which returns approximately 20 related artists dynamically generated by Deezer’s collaborative filtering and listening session machine learning models.
- **Authentic Popularity Metrics**: Deezer exposes a streaming rank score (`0` to `1,000,000`) derived from real global playback metrics. AUDY scales this score into an authentic 0–100 popularity metric (`rank / 10000`), restoring true popularity diversity (e.g., 98, 95, 86, 76, 69).
- **Working Previews and Direct Playback**: Every Deezer track includes an operational 30-second MP3 preview URL and a direct web player URL (`https://www.deezer.com/track/{id}`), enabling external listening capabilities.

### Why is Spotify still present? Is it really useful?
A critical question arises: **If Deezer provides unauthenticated access and superior recommendation endpoints, why keep Spotify in the codebase?**

1. **Compliance with RNF-05 (Multi-API Architecture)**:
   The university project rubric strictly requires AUDY to interact with at least two external information providers. Retaining `SpotifyAPIClient` along with `DeezerAPIClient` and `MusicBrainzAPIClient` satisfies and exceeds this requirement.
2. **Demonstration of the Adapter & Strategy Patterns (OOP Competence)**:
   The presence of multiple API clients demonstrates true object-oriented abstraction. The service layer (`DiscoveryEngine`) relies on polymorphic API abstractions rather than a single tightly coupled vendor, demonstrating compliance with the **Open-Closed Principle (OCP)**: new providers can be integrated without breaking existing catalog clients.
3. **Catalog Resilience & Multi-Source Fallback**:
   If an organization or user supplies configured Spotify credentials in `config.properties`, AUDY can query Spotify as an alternate catalog source when Deezer experiences network outages or region-restricted licensing.

## 2. API Specification & Client Details

### A. Deezer Web API (`com.audy.api.DeezerAPIClient`) — *Primary Engine*
- **Base URL**: `https://api.deezer.com`
- **Authentication**: None (Free public web API).
- **Endpoints Utilized**:
  - `GET /search?q={query}&limit={n}`: Fast search for autocomplete and full search matches.
  - `GET /search/artist?q={name}&limit=5`: Resolution of numeric artist identifiers from raw artist names.
  - `GET /artist/{id}/related`: Dynamic recommendation graph (up to 20 peer artists).
  - `GET /artist/{id}/top?limit={n}`: Top tracks per artist with stream rank, MP3 preview, and web player link.
- **Popularity Conversion**: $\text{Popularity} = \max(5, \min(99, \text{rank} / 10000))$.

### B. Spotify Web API (`com.audy.api.SpotifyAPIClient`) — *Modular Secondary Provider*
- **Base URL**: `https://api.spotify.com/v1`
- **Authentication**: OAuth 2.0 Client Credentials Flow (`POST https://accounts.spotify.com/api/token`).
- **Endpoints Utilized**:
  - `GET /v1/search?q={q}&type=track&limit=10&offset={n}`: Chunked pagination in blocks $\le 10$ to prevent HTTP 400 errors.
  - `GET /v1/tracks/{id}`: Dedicated track metadata lookup.
  - `GET /v1/artists/{id}`: Artist genres and metadata.

### C. MusicBrainz API (`com.audy.api.MusicBrainzAPIClient`) — *Genre & Tag Fallback*
- **Base URL**: `https://musicbrainz.org/ws/2`
- **Authentication**: Public, keyless (mandates `User-Agent: AUDY-MusicApp/1.0.0 (contact@uady.mx)` header).
- **Rate Limiting**: Strictly throttled at 1 request per second with exponential backoff and automatic retry on HTTP 503 (*Service Unavailable*).
- **Endpoints Utilized**:
  - `GET /recording/?query=recording:"{title}" AND artist:"{artist}"&fmt=json`: Retrieval of genre and style tags.

## 3. Configuration & Execution Modes

### Mode 1: Zero-Configuration Out-of-the-Box (Default Deezer Engine)
No API keys or configuration files are required. The system compiles and runs immediately:
```powershell
javac -d out (Get-ChildItem -Path src/main/java -Recurse -Filter *.java | Select-Object -ExpandProperty FullName)
java -cp out com.audy.Main
```

### Mode 2: Optional Spotify Configuration
To enable the optional modular Spotify client:
1. Copy `config.properties.example` to `config.properties`.
2. Populate your credentials obtained from the [Spotify Developer Dashboard](https://developer.spotify.com/dashboard):
```properties
spotify.client.id=your_client_id_here
spotify.client.secret=your_client_secret_here
```
The `SpotifyAPIClient` automatically detects the properties file or falls back to system environment variables (`SPOTIFY_CLIENT_ID`, `SPOTIFY_CLIENT_SECRET`).
